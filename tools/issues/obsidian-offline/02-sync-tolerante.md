## Resumo

`sync-manual` precisa processar cada nota de forma independente e relatar o que não conseguiu adotar. Também não pode reescrever o frontmatter de uma nota quando não conseguiu ler esse frontmatter.

## Motivação

Uma nota escrita à mão no Obsidian tem muitas formas de vir diferente do que o scaffold produz. Hoje, uma única nota assim derruba o run inteiro ou perde dados:

- **Sem isolamento por nota.** `_sync_all` não tem try/except em volta de cada nota. A primeira exceção marca o run como `failed`, e as notas seguintes não são processadas.
- **Datas sem aspas.** A propriedade Date do Obsidian grava `created: 2026-11-03`. O YAML lê isso como `datetime.date`, e o `json.dumps(meta)` falha em `_sync_permanent`, `_sync_moc` e no `bibliography_json` de `_sync_source` (`accessed_at`, `published_at`).
- **YAML inválido.** `parse_frontmatter` devolve `{}`. Sem `note_id`, `_sync_permanent` chama `_rewrite_frontmatter`, e o frontmatter original some sem aviso.
- **`author` em string.** `_sync_source` passa a string crua para `generate_citekey` antes de normalizá-la. `author: "Kahneman, Daniel"` vira o sobrenome `K`.
- **LIT granular:**
  - sem `chunk_id` em `20_Literature/{Citekey}/`, cai no caminho do índice e sobrescreve `sources.lit_body`;
  - com `origin` diferente de `manual` ou vazio, é ignorada em silêncio;
  - dois arquivos com o mesmo `chunk_id` se sobrescrevem.
- **Placeholders embedados.** `_Preencha a definicao._` e similares entram no embedding da ZTL.

## Contrato / comportamento

- O run conta cada nota como `new`, `updated`, `skipped` ou `failed`. Uma nota `failed` leva caminho e motivo e não interrompe as demais. O run termina como `completed` com falhas listadas. CLI e web mostram a lista.
- Com frontmatter ilegível, a nota não é tocada (o arquivo fica byte a byte igual) e entra em `failed`.
- `date` e `datetime` vindos do YAML são convertidos para string ISO antes de qualquer `json.dumps` (um helper único, usado nos três pontos).
- `author` e `authors` são normalizados para lista antes do citekey.
- Para LIT granular, cada um destes casos vira `failed` com uma mensagem acionável:
  - nota em subpasta de citekey sem `chunk_id`;
  - `origin` desconhecido;
  - `chunk_id` duplicado entre dois arquivos no mesmo run.
- Os placeholders do scaffold (reaproveitar a lista de `manual_lit`) saem do texto embedável e do checksum semântico das ZTL manuais.
