# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Run Commands

```bash
# Run the CLI (all commands go through this)
.venv/Scripts/python.exe -m zettel <command>

# Run all tests
.venv/Scripts/python.exe -m pytest tests/ -v

# Lint / format (Ruff — pyproject.toml, .cursor/rules/python-ruff.mdc)
.venv/Scripts/python.exe -m ruff check zettel tests --fix
.venv/Scripts/python.exe -m ruff format zettel tests

# Run a single test file
.venv/Scripts/python.exe -m pytest tests/test_hashing.py -v

# Run a single test function
.venv/Scripts/python.exe -m pytest tests/test_hashing.py::test_normalize_collapses_whitespace -v

# Check dependencies and config integrity
.venv/Scripts/python.exe -m zettel doctor

# Run the web UI (not a Typer subcommand — separate FastAPI app)
uvicorn zettel.web:app --host 0.0.0.0 --port 5000

# Web UI tests
.venv/Scripts/python.exe -m pytest tests/test_web.py tests/test_web_state.py tests/test_web_package.py -v

# Ask evaluation harness (offline: no LLM, no network)
.venv/Scripts/python.exe -m pytest tests/evals/ -v
.venv/Scripts/python.exe -m zettel.evals.replay evals/configs/current-ask.yaml
```

Python 3.12, venv at `.venv/`, dependencies managed via `requirements.txt`. Environment variables loaded from `.env` (python-dotenv) — not system env vars. **`SESSION_SECRET`** (web login) is read from the process environment at startup (`os.environ`), not from `config.yaml`; set it in `.env` or the host secrets (e.g. Replit). Optional **`ZETTEL_CONFIG`** points `create_app()` / `WebApplication` at an alternate YAML (used in tests).

## Architecture

Pipeline that converts PDF/Markdown files into Obsidian-compatible Zettelkasten notes:

```
harvest → extract → review → connect → garden
```

**Phase 1 (harvester.py + paging.py)**: Scans `data/inbox/`, extracts text (Docling for PDF — mandatory, no fallback, ADR-012; native for MD), generates citekeys, creates SRC (`SRC - AuthorYear - slug.md`) + literature **index** (`LIT - AuthorYear - slug.md`, no `@`, no `-index` suffix). PDF extraction runs through Docling only: if Docling is not installed or the conversion raises, harvest fails fast with `harvester.extract.PdfExtractionError` — there is no silent degradation to plain text. Before Docling is built, `assert_pdf_has_text_layer` probes the first 3 pages with `pypdfium2` (a Docling dependency — not a PyMuPDF revival) and raises `EmptyTextLayerError` for a scan, suggesting OCR, so no conversion time is spent (ADR-033). `extract_text` is also the single sanitization point: `text_sanitize.strip_invisible_unicode` removes zero-width/bidi/Unicode-tag-block characters **before** the extraction checksum, so nothing invisible to the reviewer reaches the prompt, the vault or the embedding; sources harvested before ADR-033 keep their old `extraction_checksum` until re-harvested. `run_harvest` returns a `HarvestOutcome` (`source_ids` + `skipped`): one unusable file is reported (CLI exits 1, web surfaces the message) and the rest of the inbox still processes. Resolves content-start paging (HITL, `--content-start-file` / `--content-start-book`, or silent heuristic when non-interactive): PDF **file** page where content begins + **printed** number on that page (book front matter → printed 1; journal article whose PDF starts at file p.1 may be printed p.200 via biblio `pages: 200-210`; handouts that start at 1 stay 1=1). `--skip-paging` forces file p.1 = printed p.1. Pages before the start produce no chunks. Native Markdown has **no pages** (locator is `section_path`; stray digits are not treated as pages). Chunks text via structural H3–H6 + LangChain splitter. A fence and the prose that frames it stay together: a section containing a fence is emitted whole while it fits `chunking.chunk_size * fence_section_slack` (1.5), and above that budget prose orphaned by the cut is glued back onto its fence (`1.0` restores the old always-cut behavior). This is **representation and cost, not extraction yield** — measured, a code-dominated section is still rejected as `fragmented` whether whole or split, because the model reads a mostly-illustrative passage as an example rather than a concept (ADR-014 addendum). Fence scanning lives in the leaf module **`zettel/markdown_fences.py`** (`iter_fenced_spans`, `offset_is_fenced`), not in `chunking.py`, so a pure text fact is importable without dragging in chromadb via `zettel.index`. For native Markdown a **single leading H1 is the document title, not a chapter**: its body joins the preamble and its text prefixes every `section_path` (`Documento > Capítulo > Subseção`); documents with several H1 and PDF/Docling keep the historical split. Infers `page_in_file` from a Docling page-break map in the **same Markdown dialect as the chunks** (`<!-- zettel:page-break -->` in `extracted_text`; per-page Docling export if no breaks). Regex on chunk text runs only when there is no page map and the source is not Markdown. Then `page_in_book = file - start_file + start_book` (multi-page chunks use the **first** page). Docling `prov.page_no` is the PDF file index, not the printed number. Runs five-layer duplicate detection. Indexes raw chunks into Chroma `chunks` (for dedupe/FTS); does **not** create per-chunk LIT files yet. `zettel set-paging` repairs the printed offset on an existing source without re-calling the LLM (renames granular LIT files when the page token changes). Wrong `page_in_file` on sources harvested before the Docling map needs a re-harvest (or `rechunk` when `extracted_text` already has page-break markers). Opt-in `--dump-chunks` (harvest/rechunk) writes one markdown file per source under `data/cache/chunk-dumps/` (or `--dump-dir`) with the persisted chunk text plus paging/`section_path`/overlap metadata — the same payload `extract` will see. `zettel dump-chunks --source-id @Citekey` reexports already-harvested sources without reprocessing. Opt-in `--dump-extraction` (harvest) writes `sources.extracted_text` (Docling Markdown / native MD, H1–H6 intact; PDF may include `<!-- zettel:page-break -->`) under `data/cache/extraction-dumps/` (or `--dump-extraction-dir`) as soon as the text is persisted; `zettel dump-extraction --source-id @Citekey` reexports without re-extracting.

**Phase 2 (extractor.py)**: Processes each `pending` chunk through LLM Prompt 1 (`prompts/literature_note.md`), writes a **draft** LIT note under `00_Inbox/Review/{Citekey}/` (filename `LIT - AuthorYear - pNNN - topic-NNNN.md`; same basename as the approved note) including the full source excerpt in a `zettel:auto-source-excerpt` managed block, checkpoints chunk status to `awaiting_review` after every chunk. Concepts stay `awaiting_review`. Optional `--auto-approve` for high `review_confidence`. `_check_candidate` treats the `anchor_quote` floor and ceiling **asymmetrically** (issue #153): under `anchor_quote_min_words` there is no quote to judge and the candidate is dropped, but the ceiling is `anchor_quote_max_words * anchor_quote_max_words_tolerance` (25 * 1.5 = 37) because the word count is only a proxy for what `quote_is_grounded` measures directly — losing a whole candidate over a two-word overshoot trades a formatting miss for lost content (`tolerance: 1.0` restores the hard cut). Grounding is never relaxed. A dropped candidate is recorded in `summary_json.rejected_candidates` with its `thesis`, `anchor_quote` and reason, so an audit can see what was discarded without re-running the model. There is deliberately **no pre-LLM gate on code-dominated chunks** (issue #154, closed as won't-do): the fence ratio was measured against the extract verdict and is *anti-correlated* — the corpus's highest-ratio chunk (87% fenced) is the one that produced a note, because its fence was a Python block whose comments stated the concept, so no threshold separates the cases. It would also only ever save money, never improve a note, and at ~$0.003/chunk the saving was $0.006 against one lost permanent note. Each candidate may also carry three **optional** author-judgement lists — `decision_rules`, `anti_patterns`, `named_frameworks` (ADR-034). They are optional by construction: `[]` default, no part in `_check_candidate`, and a validator that drops blanks and truncates at 3 instead of raising. `named_frameworks` keeps the author's exact wording (no translation, no acronym expansion). When any candidate states one, the LIT draft renders an `auto-decision` managed block under `## Julgamento do autor`; the ZTL carries the lists verbatim in its **frontmatter** (copied from the candidate, not from the LLM), which is what `zettel skill` reads. Managed blocks are stripped by `extract_embeddable_text`, so this text does not reach the embedding.

**Phase 2b (review.py)**: Selective approval HITL. Interactive mode prints a confidence-band report (`<=0.4` / between 0.4 and limiar / `>= limiar`), then `a`=approve all `>= literature_review.auto_approve_min_confidence` (below-threshold stay `awaiting_review`), `d`=reject submenu (`t`=all or band `b`/`m`/`h`) with `s/n` confirm (partial reject returns to menu with remaining drafts), `r`=one-by-one with shortcuts `a/r/p/q`, `q`=quit. `--yes` / `--auto-approve` keep the limiar gate non-interactively. `review_confidence` (computed in `extractor._score_review_confidence`) is **0.50 relevance + 0.30 integrity + 0.20 completeness** — no term is a length (ADR-017 addendum, issue #152). The relevance floor earns `_RELEVANCE_FLOOR_CREDIT` (0.6) of its term rather than 0, because the extract prompt deliberately compresses the scale (pick the lower level when in doubt; 5 reserved for rare fundamental ideas) and `min_relevance_score` already cuts 1–2 — mapping the floor to 0 gave a rel-floor chunk a ceiling of 0.70 against a 0.75 limiar, so it could **never** auto-approve. `integrity` is the fraction the deterministic filter kept; `completeness` is the presence of `intuition`/`limits`, structural rather than verbose. The limiar (`literature_review.auto_approve_min_confidence`, `0.75` in both `config/config.yaml` and the Pydantic default) is **not a percentile**: it sits just under the `0.80` a flawless chunk earns at the relevance floor, so a chunk auto-approves unless a defect was actually detected, and every rejection has a nameable cause. Re-measure with **`scripts/calibrate_review_confidence.py`** (rescores every chunk from the persisted `summary_json`, zero LLM/embedding calls; prints old-vs-new distributions, a threshold sweep and a **reachability table**) before touching the weights — `tests/test_calibrate_review_confidence.py` fails if any relevance level becomes unreachable. The current default was set on 1 source / 13 scored chunks: provisional, not calibrated. The very-low cut (`0.4` in `review.py`) remains an untuned heuristic; see `docs/adrs/RUNBOOK.md`. Approved drafts move to `20_Literature/{Citekey}/LIT - AuthorYear - pNNN - topic-NNNN.md`, the index is refreshed with labeled wikilinks, and concepts are deduped then marked `approved` for connect. **Dedupe is scoped to one source** (`extractor._same_source_notes`): `query_similar_notes` searches all of `permanent_notes`, so the raw hits are filtered to the candidate's own `source_id` before anything else. A hit from another source can never make a candidate redundant — it is corroboration, resolved by `connect` — so those candidates skip the dedupe LLM call entirely, which is where the cost saving comes from. Within one source the four-way decision is unchanged: `ignore` stays right for a genuinely repeated chunk, and `refine_existing` still covers an author expanding a concept as the book advances. (Global dedupe was never a recorded decision — ADR-016 documents *when* dedupe runs and is silent on scope; the globality fell out of `permanent_notes` being one collection.) **LIT notes are not embedded**: the `literature_notes` Chroma collection is gone. Nothing ever queried it — `index.py` only exposes `query_similar_notes` / `query_notes_by_ids`, both against `permanent_notes`, and ADR-036 deliberately makes a LIT target non-routable in the topic index. The note stays in the vault and in SQLite for audit (which is what `zettel skill` already reads), and the body was derived from a chunk whose text is indexed anyway — the same double-counting argument ADR-034 makes about judgement fields. Trade-off accepted: this forecloses chunk-level evidence retrieval (quoting a source verbatim in `ask`); nothing planned needs it, since ADR-044 keeps dedupe paths out of the `Retriever` and reranks `permanent_notes` candidates. Rejected drafts are deleted from the vault and marked `status=rejected` (row kept); `zettel purge-rejected` hard-deletes those chunks from SQLite (+concepts/FTS) and Chroma `chunks`, then VACUUMs `state.db` and `chroma.sqlite3` by default (`--no-compact` skips).

**Phase 3 (connector.py)**: Takes `approved` concepts, uses RAG (hybrid `Retriever`) for context, calls Prompt 2, writes ZTL notes. `literature_ref` points at the **granular** approved LIT for that chunk (fallback: source index), now with `with_alias=True` so the link reads `p. 42 - Topico`. The `## Fonte` section and the frontmatter carry a **structural** `page`, read from `chunks.page_in_book` on the row `_literature_ref_for_chunk` already fetched — `source_locator` stays as a secondary descriptive field but is LLM-authored prose from Prompt 1 (the extractor only backfills it when empty or under 3 chars), so it is not the page of record. `page` is omitted, never null, for native Markdown, which has no pages (ADR-013). `chunk_id` is also in the frontmatter, so a ZTL has a structural trail back to its chunk.

**Citation provenance (`zettel/citation.py`, ADR-051)**: a ZTL is mechanically citable, and the citation is derived by code, never through the LLM. `resolve_citation(source, chunk, anchor_quote)` is the single definition used by `connect` and by the manual `new-note ztl --from-lit` scaffold.
- **Page.** `page` is the page the grounded `anchor_quote` actually sits on, not just the chunk's first page. `paging.locate_quote_pages` searches the Docling page map in `sources.extracted_text` from the chunk's `page_in_file` up to three pages further. It matches the anchor's first and last five folded words separately, so a quote crossing a break gives `p. 42-43` and an editorial ellipsis is tolerated. When there is no page map or no match, it falls back to `chunks.page_in_book`. `citation_page_confidence` records which rule applied (`quote`/`chunk`).
- **Frontmatter.** It gains `citation` (ABNT author-date via `format_abnt_in_text`, e.g. `(KAHNEMAN, 2011, p. 45)`; no page for native Markdown) and `anchor_quote` (copied verbatim from the candidate).
- **Body.** An `auto-evidence` managed block under `## Fonte` holds the citation and the literal passage. Being a managed block, it is stripped by `extract_embeddable_text`, so the quoted text never reaches the embedding.
- **What is and is not guaranteed.** The anchor is chosen per thesis, not per chunk, and grounding proves it is literal. Whether it *supports* the thesis is still the model's choice, checked by the human in `review`.

**Corroboration between sources (`_corroborating_note_ids`)**: when a hit the `Retriever` already returned for the RAG context is a search seed (`hop == 0`) whose cosine similarity clears `linking.corroborates_min_similarity` (0.85) and whose note belongs to a **different `source_id`**, connect injects a `corroborates` edge (capped at `linking.corroborates_max_edges`, default 3). Two authors converging on one idea is the product of research, not a duplicate to collapse. This costs **zero extra embeddings and zero LLM calls** — the search already ran. Persisted with `origin='derived'`, not `'llm'` — an audit querying `origin='llm'` must not sweep up an edge no model proposed (only `manual` overrides graph weight, so weighting is unaffected). One row is written, not the symmetric pair: `graph.expand_notes` iterates edges undirected and `rebuild_auto_backlinks` renders the inverse (`corroborado por`) on the other note, exactly as `extends` already works. Processing order closes itself — if A was connected before B existed, B links B->A on its own run.

`corroborates` is deliberately **absent from `prompts/permanent_note.md`** and `tests/test_prompts.py` pins that absence. Corroboration is a fact about authorship, not a judgement about content; offered in the relation menu the model would emit it rhetorically ("this note also agrees") and the signal would collapse into `supports`. `_demote_llm_corroborates` downgrades a model-emitted `corroborates` to `supports` at the LLM trust boundary — applied to `note_output.connections` only, *before* the injection, so the edges this module asserts survive. Same pattern as ADR-034 (judgement lists copied from the candidate, never through the LLM) and a deliberate carve-out from ADR-043 (which gates LLM *judgement*; this edge is derived by code).

Its graph weight is **0.45** — below `related` (0.5), on purpose. Weight governs **traversal, not importance**: N sources on one idea form a clique of near-identical notes that is exactly what a thesis writer wants to read and the worst thing to spend `max_neighbors` slots on (`config.yaml` runs `max_hops: 5, max_neighbors: 16`), since every such hop returns a paraphrase instead of new information. The relation earns its prominence in the rendered `## Conexões` / `auto-backlinks`. `tests/test_config.py` pins `corroborates <= related`. Accepted and *not* mitigated in code: `gardener` cluster cohesion and `_build_rag_context`'s graph group can both see paraphrases; if that shows up in practice, collapse corroborates cliques to one representative + count at those two context builders. Connection `related_note_id` values are canonicalized (strip `ZTL -` / wikilink wrappers to the ULID) and **dropped** if the target is missing from SQLite or the file is gone — no phantom `[[ZTL - ZTL - ULID]]` wikilinks. `auto-backlinks` is rebuilt from incoming `note_connections` (live file stem + inverse relation), not append-merged. RAG context has three provenance groups: embedding neighbours, graph neighbours, and **distant analogies** (notes outside the candidate's taxonomy bucket, local floor `linking.distant_analogy_min_similarity` — `RelevanceFloorConfig` is untouched). Distant-analogy connections go to `auto-connections`, not `note_connections` (ADR-043). `{domain}` in Prompt 2 comes from `domain.name`; few-shots from `domain.examples_path` (ADR-042).

**Phase 4 (gardener.py + gardener_assign.py)**: Hybrid MOC pipeline — embeds category labels from `gardener.topics_path` as `{pilar}: {categoria}` (`category_label_template`; `domain` stays available on a custom template), assigns notes to taxonomy buckets, clusters with UMAP+HDBSCAN (or KMeans) **within each category**, scores graph cohesion via `note_connections`, then routes each cluster through `_process_cluster` with at most **one LLM call** (incremental preferred when note overlap ≥ `overlap_threshold` or category already has a MOC; otherwise `moc_generation` with `suggested_category` hint). New MOC topics validated against **categorias** (substring match; rejected if `strict_topics: true`). Category names must be globally unique. After each MOC write/update, `moc_backrefs.sync_moc_backrefs` maintains `auto-moc-backrefs` blocks on linked permanent notes. `zettel garden --recreate` purges pipeline MOCs (`clear_moc_backrefs` first) and regenerates — required after a label-template or taxonomy change. HDBSCAN noise stays out of MOCs; notes remain navigable via graph edges.

**Phase 4b (gardener_hub.py)**: Complementary hub-anchored MOCs via `zettel garden --hubs` — ranks permanent notes by weighted graph degree, expands neighborhoods with BFS (`expand_notes`), deduplicates overlapping neighborhoods, then routes through `_process_hub_cluster` (incremental if `hub_note_id` already has a MOC; else `moc_hub_generation` with LLM-derived topic). Persists `origin='hub_pipeline'` with `hub_note_id` in frontmatter; same `sync_moc_backrefs` / `clear_moc_backrefs` lifecycle. `garden --hubs --recreate` purges only hub MOCs; taxonomy pipeline MOCs (`origin='pipeline'`) are untouched.

**Phase 2c (summarize.py + catalog.py)**: `zettel summarize` resumes each chapter from its **real text** (`chunks.text` reassembled in `chunk_index` order — not the 280-char `summary_json` the extract kept, which only exists for chunks the pipeline accepted) and reduces the chapter summaries into one source summary. ADR-047. The chapter summary **is** embedded (Chroma `chapter_summaries` + FTS5 `fts_chapter_summaries`) and is the unit of search; the source summary is **not** embedded — nothing would read it, and a second write-only collection is exactly what removed `literature_notes`. Both are **routing artifacts, never evidence**: they say where to look and are never quoted as support, which is what keeps an LLM-authored artifact clear of ADR-043's gate and of ADR-034's double-counting argument. That boundary is enforced, not just documented — `tests/test_catalog.py` parses `zettel/ask.py` and fails if it ever reaches `search_chapter_summaries` / `query_chapter_summaries` / the chapter floor. Regeneration is gated on `chapter_checksum` (the same gate that skips re-chunking): a chapter whose `summary_checksum` still matches costs **zero** LLM calls, so re-running on a settled vault is free. A chapter above `summarize.max_input_chars` is map-reduced, its partials folded back through the same prompt. A stale summary is flagged, never deleted. The two vault surfaces are managed blocks on the **existing** literature index note: `auto-source-summary` under `## Resumo geral` and `auto-chapter-map` under `## Mapa de capitulos` (title, page range, note count, summary, wikilinks to that chapter's LIT and ZTL); `summarize._write_blocks` owns both headings, mirroring `topic_index._write_block`. `generate_summaries` (costs money) and `refresh_chapter_map` (deterministic, free) are deliberately separate functions, and `connect` calls the second one so per-chapter note counts stay live without regenerating text — same pattern as `sync_moc_backrefs` after a MOC write. `preflight.estimate_summarize` is a pure function (ADR-037); in `run-all`, summarize runs **after** the `--dry-run` gate so `--dry-run` still spends nothing.

**`zettel catalog "assunto"` (catalog.py)**: answers a *library* question — which sources treat a subject, which chapters, and **how many permanent notes each chapter produced**. **No LLM call, ever**: the answer is a ranked table plus a SQL aggregate, and routing it through `prompts/ask.md` would ask a model to enumerate a count it could hallucinate. Two signals fused at the chapter level, each row declaring its provenance (ADR-010's contract): **signal A** walks `Retriever.search_notes` hits back through `note -> concepts.chunk_id -> chunks.chapter_id` (free, and the strongest evidence the vault has — a chapter found this way never faces the chapter floor, since its evidence is a note that already cleared the note floor); **signal B** is `Retriever.search_chapter_summaries`, which covers the chapter that produced no note at all (zero extract yield, or no `connect` yet). The note count is `db.get_chapter_note_counts` — `COUNT(DISTINCT note_id)`, so a merged note counts once. `CatalogResult` carries `sources` **and** `candidates`, so an over-strict floor is visible instead of silently empty. CLI-only, like `ask`/`article`/`skill`.

**The chapter floor is its own knob, measured on its own distribution.** `retrieval.chapter_floor` is a separate `RelevanceFloorConfig` from `retrieval.relevance_floor`; `_apply_relevance_floor` takes its config as a parameter (identical reasoning, independently measured numbers — the note path is untouched). Inheriting the note floor would be a category error whatever the number: a chapter summary is longer and more diffuse than a note, so it scores lower for the same question. **Measured 2026-09-07** over 71 summarized chapters (`ollama/qwen3-embedding@1024d`): off-domain queries top out at `0.693`, self-match bottoms at `0.745`, margin `0.052` — so the floor belongs in `(0.693, 0.72]` and is set to **`0.70`**. The initial `0.60` let all six off-domain probe queries through. That it equals the note floor is two independent measurements agreeing, **not** inheritance, so `tests/test_config.py` pins them as separate objects and deliberately does *not* assert the values differ. The margin is thin: a few off-topic chapters land at `0.707`–`0.723`, and the probe warns that raising toward `0.72` costs real recall. Re-measure with `scripts/probe_relevance_floor.py --collection chapter_summaries` after any embedding change — the number does not transfer between models.

**sync.py**: Not part of the linear pipeline — scans `10_Sources/`, `20_Literature/` (including citekey subfolders), `30_Permanent/`, `40_MOCs/` for manually-created or hand-edited notes (via `zettel sync-manual`), assigns IDs/checksums if missing, indexes them into ChromaDB/StateDB, and writes suggested connections into an `auto-connections` managed block. Manual MOC sync also calls `sync_moc_backrefs`. It also closes the graph loop: `_extract_body_edges` persists `[[wikilinks]]` found in a note's body (outside managed blocks `auto-connections`/`auto-backlinks`/`auto-moc-backrefs`) as `related` edges with `origin='manual'` in `note_connections`, never downgrading an already-typed edge. Graph expansion weights `origin=manual` as `manual` (0.95), not thematic `related` (0.5) (ADR-009). `zettel sync-manual --rebuild-graph` (`rebuild_manual_edges`) backfills these edges for the whole vault from bodies already in SQLite. After the scan, `repair_permanent_links` rewrites bare/double-prefixed `[[ZTL - ULID]]` targets to the current file stem and rebuilds every ZTL `auto-backlinks` block from the graph. Sync is also the **adoption point for manual images**: `assets.adopt_vault_images` copies `![[img.png]]` / `![alt](path)` refs into `90_Assets/` content-addressed, rewrites the ref and registers an `assets` row (`status='pending'`, described later by `extract`). Not gated on `images.enabled` (that flag governs LLM cost); the original file is never deleted (ADR-031).

**new_note.py (`zettel new-note`)**: Scaffolds manual vault notes (`ztl`/`src`/`lit`/`moc` aliases) with `origin: manual` — does **not** touch SQLite/Chroma. SRC/LIT citekey from `--citekey`/`--source-id` or provisional derivation; `src` also writes the source's literature **index** (mirroring harvest, so the SRC wikilink is not born dead); LIT `--granular` → chunk file under `{Citekey}/`. Index afterward with `sync-manual`. The one exception that does touch the stores is `new-note ztl --from-lit <path|chunk_id>`, which lives in **manual_lit.py**. For a hand-written ZTL that should stay in the author's voice, `zettel suggest-links` writes RAG (including distant analogies) into `auto-connections` without Prompt 2 or `ConnectRejected`.

**manual_lit.py**: Adoption of hand-written granular LIT notes and the LIT→ZTL path (ADR-030). `adopt_manual_literature` synthesizes the `chunks` row a manual note never had (plus a per-source `{source_id}::ch000` "Manual" chapter — `chunks.chapter_id` is NOT NULL with an FK), rebuilds `summary_json` by parsing the note's own `## Resumo` / `## Conceitos-chave` / `## Candidatos a Nota Permanente`, takes `chunks.text` from the `auto-source-excerpt` block, writes `status='persisted'` and calls `review._refresh_literature_index`. Like the pipeline path, it does not embed (ADR-030's rationale loses one of its five free behaviours; the other four stand). Idempotent by checksum over excerpt+body. **Manual notes never enter the review gate** — that gate is scoped to LLM output. Deliberately does *not* write the Chroma `chunks` collection (its thresholds are calibrated for harvest dedupe on raw L2). `create_permanent_from_literature` derives a `PermanentNoteCandidate` from the note; with `--llm` it persists an `approved` concept and calls `connector.run_connect(..., origin="manual")` (same Prompt 2 / RAG / relations / backlinks); without it, writes a pre-filled scaffold and consumes any already-approved concepts for that chunk/thesis (`status=noted`) so a later `connect` cannot duplicate it. `sync._sync_literature` dispatches to adoption only for `origin: manual`; pipeline granular LITs keep the lightweight `update_chunk_review` path so their real extracted text is never overwritten.

**purge_source.py (`zettel delete-source`)**: Irreversible full source removal by `@citekey` — vault (SRC, LIT index/granular, Review drafts, assets), SQLite cascade (source/chapters/chunks/concepts/assets/files), Chroma (`sources`, `chunks`). Default keeps linked ZTL but strips dead wikilinks vault-wide and clears `source_id` on those notes; `--delete-permanent` removes ZTL too. VACUUM by default (`--no-compact` skips), same pattern as `purge-rejected`.

### Hybrid retrieval + GraphRAG (retrieval.py, graph.py, ask.py, article.py)

- **retrieval.py (`Retriever`)**: single composition point for note/chunk lookup. Fuses ChromaDB dense search with SQLite FTS5 BM25 via **Reciprocal Rank Fusion** (`retrieval.rrf_k`), then applies an absolute relevance floor, then optionally expands the surviving seeds over the note graph. `search_notes()` returns a `NoteSearchResult(hits, candidates)`: `hits` is what cleared the floor (+ graph neighbours, `hop >= 1`) — what callers should use as evidence; `candidates` is the raw RRF-ranked pool *before* the floor, always populated, so a caller can show "what was closest" even when `hits` is empty. Each `RetrievedNote` carries provenance (`vector_rank`/`bm25_rank`/`hop`/`via`/`passed_floor`). `retrieval.mode` = `hybrid` (default) or `vector` (legacy); degrades to vector-only when `StateDB.fts_enabled` is False. **Consumers that migrated**: connector RAG (`.hits`), sync suggestions (`.hits`), the `ask` command (`.hits` + `.candidates`), the `article` command (`.hits` + catalog). **Deliberately NOT migrated**: extractor dedupe and harvester layer-3 — their thresholds (`dedupe_threshold`/`duplicate_chunk_threshold`) are calibrated on raw L2 distance.
- **Absolute relevance floor (`RelevanceFloorConfig` in config.py)**: RRF's fused score is purely *positional* — dense kNN always returns the N closest notes in the corpus regardless of whether any are actually relevant, so a totally off-topic question gets a similarly "confident" score to a genuinely answerable one. `_apply_relevance_floor` in retrieval.py gates each hit in this order (sets both `passed_floor` and a human-readable `floor_reason`):
  1. `absolute_min_similarity` (default `0.15`) — a hard backstop: if similarity is below this, the hit fails even with bm25 support. Set well below the main floor so it doesn't undermine BM25's main use case (rescuing jargon/acronyms the embedding underrates).
  2. `bm25_hit_bypasses_floor` + **two** gates, `bm25_bypass_max_rank` (default `5`) and `bm25_bypass_min_coverage` (default `0.5`) — a bm25 hit bypasses the similarity check only when it ranked within the cutoff **and** contains at least half the query's FTS terms. Failing either is not a rejection: the hit falls through to the similarity check like any other. Rank alone was insufficient and this is the second fix in that family — before the rank cutoff, *any* bm25 presence bypassed unconditionally; after it, rank was still only a **relative** test, and since `_fts_match_expr` ORs the query's terms, a match pool smaller than the cutoff made "top 5" mean "everything". Measured 2026-09-09 on 62 notes, "como fazer risoto de cogumelos" returned 4 notes all rescued by the single common verb *fazer* at similarity 0.58–0.64. Coverage is the **absolute** half (how much of the question is actually in the note); it was chosen over a minimum matched-term count because a one-word jargon query (`ARIMA`) matches one term at coverage `1.00`, and a `>= 2` rule would make the bypass unreachable for exactly the acronyms it exists to rescue. Off-domain hits fell 31 -> 1 at **zero** in-domain cost; `connect`/`sync` lost nothing either (their bypasses all had similarity >= 0.734 and passed anyway). `state.fts_query_terms` is the single definition of "the query's terms", shared with `_fts_match_expr` so the denominator cannot drift; only hits inside the rank cutoff are folded, so the cost is bounded and flat in corpus size (~1.0 ms -> ~4.8 ms in `_bm25_notes`). `0.0` restores the rank-only behaviour. ADR-003 addendum.
  3. `min_vector_similarity` (default `0.70`) — the default gate for hits without a strong lexical match. Re-measure with **`scripts/probe_relevance_floor.py`** (no LLM calls; embeds only its probe queries) before touching it, and after **any** embedding change — the number is meaningless across models. On `ollama/qwen3-embedding@1024d` it separates off-domain queries (top-1 ~`0.67`) from in-domain (~`0.80`); the `0.65` this file once documented let noise through. The script also verifies that stored and query vectors are unit-normalised, which is what makes the `1 - distance/2` cosine conversion valid at all (collections carry no explicit `hnsw:space`, so Chroma's default squared-L2 applies). `tests/test_config.py` pins `config.yaml` to the schema default so the two cannot drift apart.
  4. A weak bm25-only hit with no vector data at all fails (insufficient evidence either way).
- **Topic-index boost (`retrieval._add_topic_index_seeds`, ADR-036)**: when the question contains a term from the topic index, the routed note is fetched with `VectorIndex.query_notes_by_ids` (Chroma search space restricted to that id) so it arrives with a **real distance** and faces `_apply_relevance_floor` on the same evidence as any other candidate — never as a bypass; injecting it without a distance would recreate the unconditional-BM25-bypass bug. It is merged into the vector pool and re-sorted by distance, so it gets its true rank. `retrieval.topic_index_boost` (default true) and `retrieval.topic_index_max_seeds` gate it; a hit that came this way carries `RetrievedNote.origin == "topic_index"`, shown by `ask --show-context`. Costs one extra query embedding, and only when a term matches.
- **graph.py (`expand_notes`)**: BFS (Python, not SQL CTE) over `note_connections`, undirected, weighted by relation type (`DEFAULT_RELATION_WEIGHTS` in config.py; `contradicts` highest — it's the signal embeddings miss) and hop decay. Seeds keyed by their RRF score via `seed_weights`. One batched query per frontier (`StateDB.get_connections_for_notes`). Only fed seeds that cleared the relevance floor.
- **ask.py (`run_ask`)**: `zettel ask "..."` — retrieves with the `Retriever`, builds a cited context from `.hits`, calls `prompts/ask.md` (PT-BR, answers only from the vault, says "no evidence" rather than hallucinating). When `.hits` is empty (nothing cleared the floor), the LLM is **not called at all** — a deterministic "no evidence" answer is returned, while `AskResult.candidates` (mirrors the Retriever's raw pool) still lets the CLI's `--show-context` table show what was closest, each row carrying `vector_similarity`, `bm25_rank` and `floor_reason` (the exact text explaining the floor verdict, e.g. "match lexical forte (bm25 rank 3 <= 5)"). `AskResult.retrieval_params` snapshots every threshold actually used for the call (mode, topk, rrf_k, the three relevance-floor knobs, graph expansion settings); the CLI renders it as a "Parametros de recuperacao" table when `--show-context` is passed, so the reader can see the exact rules a run was judged against without opening config.yaml. `build_ask_note_body`/`save_ask_note` persist the answer as a `.md` note in `00_Inbox/` with a full-provenance "Fontes consultadas" section (built from `.sources`, i.e. what actually fed the answer, including `floor_reason`). Uses the same deterministic LLM cache as connector (`compute_llm_call_checksum`).
- **article.py + article_graph/ package (`run_article`)**: `zettel article "tema" --style blog|academic` — LangGraph StateGraph for long-form writing (not short QA), CLI-only (ADR-028; not exposed in the web UI). Nodes: query enricher → incremental hybrid search (merge by note_id) → context HITL → catalog (sources/ABNT/assets) → outline HITL → per-section draft (blog light mentions or academic ABNT; anti-AI prose block) → assemble → personality rewrite (`config/personalities.yaml`; `neutral` skips LLM) → judge loop (`max_judge_iterations`, `judge_min_score`) → verify/save to `00_Inbox/ART - ...md` without Chroma indexing. Reuses `Retriever`, `format_abnt_in_text`, LLM cache. **Academic citations are per note** (ADR-051): `CatalogNote.cite` and `.anchor_quote` are read from `notes.frontmatter_json`, not from the truncated body, and `_pack_section` hands each evidence note its own `citacao_abnt` (with page) plus a `citacao_direta` when present. A note with no `citation` key falls back to its source's author-date citation. The academic prompt makes paraphrase the default and allows quotes only as a verbatim `citacao_direta`. `verify_article` flags any quoted span of four or more words that is not a substring of a catalog anchor. CLI uses LangGraph `interrupt()` + Rich prompts; MemorySaver checkpointer per run. `zettel/article.py` holds the domain helpers (catalog, outline, drafting, assembly, personality, judge); orchestration is the `zettel/article_graph/` package (ADR-029, same split pattern as `zettel/harvester/` from ADR-027): `runtime.py` (state contract, run-option resolution, result mapping), `search.py` (the four pure retrieval functions behind the one node with real logic — multi-query search, MOC boost, extra graph hops, the `retrieval_params` snapshot), `nodes.py` (13 `node_*` adapters + 3 `route_after_*` routers), `graph.py` (`build_article_graph` / `run_article_graph` — the topology to read first). Two seams a change here must preserve: **(1)** every LLM call routes through `zettel/article.py`'s `call_llm`/`get_llm` module globals — no package module imports them from `zettel/llm.py` directly, since `tests/test_article.py` / `tests/test_article_graph.py` monkeypatch them there; **(2)** `build_article_graph` and `run_article_graph` must stay in the same module (`article_graph/graph.py`) because `run_article_graph` resolves `build_article_graph` as a module global and `tests/test_article_graph.py` monkeypatches `zettel.article_graph.graph.build_article_graph`.
- **FTS5 in state.py**: `fts_notes`/`fts_chunks` virtual tables (`unicode61 remove_diacritics`), kept in sync inside `upsert_note`/`upsert_chunk` (explicit populate, not triggers). `_fts_match_expr` quotes every token to neutralize FTS5 operators — never interpolate raw user text into a MATCH — and drops high-frequency PT-BR stopwords (`_PT_STOPWORDS`: articles, prepositions, conjunctions, pronouns) before building the OR-joined MATCH expression. Without this, a token like "que" matches nearly every note in the corpus, which both pollutes BM25 ranking generally and silently defeats the relevance floor's bm25-bypass (a "hit" on a stopword isn't real evidence). `rebuild_fts()` is wired into `zettel reindex`.

### Ask evaluation harness (zettel/evals/, tests/evals/, evals/)

- **Research infrastructure, isolated by assertion** (ADR-038). `zettel/evals/` is **never** imported by `harvest|extract|connect|ask` — a test spawns a subprocess importing those and fails if `zettel.evals` appears in `sys.modules`. Two more tests make `socket.connect` and `llm.call_llm` raise, so CI can never pay for a run. It reads only the public `AskResult` surface (`sources`, `candidates`, `floor_reason`, `llm_called`).
- **`manifest.py`**: `RunManifest` + `manifest_identity` — two runs are comparable only when condition, fixture hash, question-set hash, model ids, the `FLOOR_KEYS` subset of `retrieval_params` **and `commit_sha`** match, so a cross-commit comparison is a deliberate act. `build_manifest` refuses an incomplete manifest and any *value* shaped like a credential (`sk-`, `api_key`, `Bearer `, `ghp_`) — it scans values, not field names, so `max_input_tokens` is not a false positive.
- **`score.py`**: verdicts separate routing from representation — `routing_miss` (target never in `candidates`), `floor_reject` (in `candidates`, gated), `answer_fail` (used, rubric missed), `ok`, `unknown` (gold names no target). A question marked `expect_no_evidence` passes only when `hits` is empty **and** the LLM was never called. The only answer check is the gold's declared `answer_must_contain` substrings; nothing infers hidden reasoning.
- **`replay.py`**: `python -m zettel.evals.replay evals/configs/<name>.yaml [--out ...]` scores recorded trajectories into stable JSON (sorted keys, no timestamps). `trajectory_from_ask_result` is the bridge a future live runner should record through. `evals/results/` holds the committed baseline; `.eval-work/` is gitignored.
- **Claims guardrail**: a null result is valid, and no comparison between conditions may be published without an identical question/model envelope on both sides.

### LLM cost pre-flight (preflight.py)

- **preflight.py**: `estimate_extract` / `estimate_connect` / `estimate_article` return a frozen `PreflightEstimate` (phase model, item count, input/output tokens, USD) from SQLite + config — **pure functions, no LLM call, no prompt** (ADR-037). Tokens are `chars // 4`; price comes from `pricing.estimate_llm_cost` (LiteLLM map; unknown/local model = $0). The `run_*` functions are **unchanged**, so the web worker and every test calling them directly cannot acquire a new way to block. `cli.deps.preflight_gate` renders the Rich panel and asks; `--yes` **or** a non-TTY stdin passes straight through, and a declined confirm exits 1 before any client is constructed. Connect's RAG context is sized as `linking.topk + graph_expansion.max_neighbors` entries at `RAG_CHARS_PER_NOTE` (250) — mirroring what `connector._build_rag_context` actually renders (wikilink + 150-char snippet + tags), not the average note length. Article reports an explicit **floor** (enrich + outline + one draft per section + assemble + judge ceiling). Output targets live in `extraction.preflight_output_tokens_per_chunk` (800) and `linking.preflight_output_tokens_per_note` (1200) — targets for the estimate, **not** caps. The SQLite response cache is deliberately not discounted, so the number is an upper bound. Wired into `extract`, `connect` and `article` only; `garden`/`harvest`/`ask` have none by design.

### Agent Skill export (skill_export.py, topic_index.py)

- **skill_export.py (`run_skill_export`)**: `zettel skill --source-id @Citekey | --moc-id ULID | --topic "categoria"` projects an **already-approved** vault slice as a flat Agent Skill under `<vault>/.claude/skills/<slug>/` (`--out` names the directory that *holds* packs, so the pack is always `<out>/<slug>`). Deterministic: **no LLM call, no writes to SQLite/Chroma** — same vault state, same bytes (ADR-035). Layout is flat by design (no child skills): `SKILL.md` + `notes/<slug>-<id6>.md` + `cheatsheet.md` + `glossary.md`. Selectors are mutually exclusive; a `--topic` matching more than one MOC topic is an error listing candidates, not a silent union. Prefers permanent notes; approved granular LIT is the fallback **only** for a source slice (a MOC/topic *is* a set of ZTL, so empty means empty). `auto-source-excerpt` is replaced by a marker unless `--include-excerpts` — citekey, locator, thesis and wikilinks always survive. Only the **Core** section is budgeted (`SKILL_TOKEN_BUDGET`, chars/4); the Topic Index and Note Index are the routing table and are never truncated, so an oversized slice yields a bigger `SKILL.md` (the CLI prints the estimate) rather than unreachable notes. `cheatsheet.md` is built from `decision_rules`/`anti_patterns` (ADR-034), `## Limites` and `contradicts` edges. Ranking is `relevance_score + weighted graph degree`, ties broken by `note_id`. `--overwrite` **clears** the pack directory (generated output, not a vault note). CLI-only — not exposed in `web_app.py`.
- **topic_index.py (`build_term_map`, `sync_topic_index`)**: the single definition of "which terms route to this note" — named frameworks first (the author's vocabulary), then tags, falling back to the thesis head only when a note has neither. PT-BR stopwords (`state._PT_STOPWORDS`) are dropped at the edges, accent/case variants merge, and each term keeps at most 3 notes. Shared so the pack's Topic Index and the vault's own index blocks cannot drift apart. `sync_topic_index` writes **two surfaces in one call** (ADR-036): the `auto-topic-index` managed block on each MOC (`_write_block` owns the `## Topic Index` section, so the body builders do not scaffold it) and the mirrored `topic_index_terms` rows in SQLite, replacing a scope wholesale so a removed tag disappears. Literature index notes do **not** carry this block (amendment 2026-09-10): the source scope never seeded retrieval. Hooks: `review._clear_source_topic_index` (drops leftover `scope_kind='source'` rows and strips the vault section) and `moc_backrefs._sync_moc_topic_index` (MOC scope, ZTL targets -> routable), with `clear_moc_backrefs` / `delete_source_cascade` cleaning up and `rebuild.rebuild_topic_index` backfilling MOCs (and clearing source leftovers) during `zettel reindex`.

### Five-layer duplicate detection (`harvester/pipeline.py` `_process_file`)

Runs in order, each layer cheaper/more certain than the next, before a file is treated as a new source. Layers 1, 2 and 5 live in `harvester/duplicates.py`; layers 3 and 4 in **`harvester/biblio_dedupe.py`**.

1. **File hash** (`get_file_by_checksum`): identical bytes at a different path → treated as a renamed copy, reuses the existing `source_id`, no reprocessing.
2. **Extraction hash** (`get_source_by_extraction_checksum`): different bytes but identical normalized extracted text (e.g. same paper re-exported PDF vs. Markdown) → reuses the existing source.
3. **DOI / ISBN exact** (`find_exact_bibliographic_match`): an **identity**, not a similarity — reuses the existing source with no prompt. `sources.doi` / `sources.isbn` are indexed columns promoted out of the `bibliography_json` blob and stored already normalized (`normalize_doi` strips a `doi:` scheme or doi.org URL and requires the `10.` registrant prefix; `normalize_isbn` strips punctuation and requires 10/13 digits). DOI is checked before ISBN — a DOI identifies the work, an ISBN one edition of it.
4. **Title + author** (`find_title_author_candidates`): a **heuristic**, so it always asks and never merges on its own. Requires normalized title *and* a shared author surname — title alone matches a book against its own chapters, authors alone matches everything a prolific author wrote. `normalize_title` reuses `hashing.fold_for_match` and drops the subtitle after `:` (where cataloguing diverges most); `author_surnames` compares last tokens, so "D. Kahneman" matches "Daniel Kahneman" without a fuzzy threshold to tune. A differing year is **reported, never used to reject** (2nd edition vs 1st is exactly the user's call). Unlike layer 5 it ignores `non_interactive_duplicate_action` and defaults to **`continue`** without a TTY: merging is the irreversible direction (ADR-011 records there is no way to separate two documents again), and title collisions between genuinely distinct works are common.
5. **Semantic similarity** (`find_semantic_duplicate_candidates`) — **off by default** (`harvest.semantic_duplicate_enabled: false`): samples chunks from the new file, queries ChromaDB for near-duplicate chunks (`harvest.duplicate_chunk_threshold`, default 0.88) belonging to other sources. If candidates are found, `resolve_duplicate_decision` either prompts interactively (Rich `Prompt`) or applies `harvest.non_interactive_duplicate_action` (`skip`/`continue`/`abort`) — controlled by the `harvest` CLI flags `--yes`, `--skip-duplicates`, `--force`.

**The layer-5 flag gates write and read together, and must never be split.** It answers one binary question per ingested file, but the price is embedding *every chunk of every source* to keep the target index alive — the largest single slice of harvest wall-clock. Gating only the write would leave the check querying an index the pipeline stopped populating: a **silent false negative**, not an error. Three points, one flag: `chunking.chunk_and_persist` (no `idx.upsert_chunk`), `pipeline._process_file` (layer 5 not consulted), `rebuild.run_reindex` (the `chunks` collection is not touched — not even reset by `--force`, since resetting without repopulating would empty it as a side effect of a "rebuild"). SQLite and FTS5 keep every chunk either way. Turning it on requires `zettel reindex --collection chunks` to populate the target index. With it off, `duplicate_chunk_threshold: 0.88` — the uncalibrated knob ADR-011 flags — is inert.

Layers 3 and 4 are pure SQLite and run **before any embedding**, so they make the common case cheaper. They are deliberately **not** a replacement for layer 5: semantic similarity is the only net for material whose metadata is unusable (a handout, a PDF with no cover page, a title the extractor guessed). Both run after `build_bibliographic_metadata` and before `generate_citekey`, so a duplicate never burns a disambiguated citekey (`Silva2020Obra` → `Silva2020Obraa`) on its way to being rejected.

Note the scanned-PDF case: a scan never reaches these layers at all — ADR-033's `assert_pdf_has_text_layer` fails it fast suggesting OCR. The duplicate appears only *after* the user OCRs it, where layers 1–2 miss (different bytes, different text) and layer 3/4 catch it.

Every decision is recorded via `db.record_duplicate(run_id, layer)` (`file`/`content`/`biblio`/`semantic`) and surfaced in `zettel status` / the `harvest` command's summary output.

### Key shared infrastructure

- **config.py (`AppConfig` / `load_config`)**: schema Pydantic + fallback de fabrica. Fonte operacional: `config/config.yaml` (toda chave do schema deve estar no YAML, exceto `gardener.allowed_topics`). `load_config` faz `AppConfig(**yaml)`; chave ausente usa o Field default. Segredos ficam no `.env`. Identidade LLM é por fase (`llm.harvest` … `llm.images`: provider + model + base_url); knobs de amostragem ficam em `llm.temperature` / `top_p` / `max_retries` / `prompt_cache`. Embedding continua em `embedding.*`. **`domain`** is top-level (`name` fills `{domain}` in extract/connect/garden prompts; `examples_path` is the few-shot YAML, anchored like `topics_path` — ADR-042). **`vault_timezone`** (IANA, default `America/Sao_Paulo`) governa timestamps de frontmatter do vault e exibição na web (ADR-041).
- **crashlog.py**: a fault inside a native extension (docling-parse, torch, onnxruntime) kills the process with no Python traceback. `enable_crash_log()` runs first thing in `cli.main()` and in the web `lifespan`, and points `faulthandler` at `data/logs/crash-<ts>-<pid>.log`: a header (time, pid, argv) plus, on a fatal signal, every thread's Python stack. The file is deleted on a normal exit, so `data/logs/` only holds crashes, and `zettel doctor` flags any left over. The function does nothing when faulthandler is already on (pytest, `-X faulthandler`). Stdlib only, so `--help` stays light. A heap-corruption fail-fast (`0xc0000374`) is not catchable and leaves just the header; the Windows Event Log still names the faulting DLL.
- **time.py**: ponto único de timestamps — `now_utc_iso()` para SQLite; `now_vault_iso` / `now_filename_ts` / `vault_date_iso` para vault; `format_local_datetime` para a UI (filtro Jinja `local_dt`). Timestamps naive são rejeitados; sem caminho legado.
- **state.py (StateDB)**: SQLite with WAL mode. Tables: files, sources, chapters, chunks, concepts, notes, mocs, assets, llm_cache, note_connections, runs, **`web_jobs`**, **`web_job_events`**, plus FTS5 virtual tables fts_notes/fts_chunks/**fts_chapter_summaries**. `chapters` and `sources` carry `summary`/`summary_topics`/`summary_checksum`/`summary_model`/`summary_updated_at` (ADR-047); `upsert_chapter` deliberately does **not** list them in its `DO UPDATE SET`, so a re-harvest preserves the summary and the checksum divergence is what marks it stale. `runs` and `sources` store estimated LLM/embedding cost and token totals. `get_web_dashboard()` feeds the web overview. All pipeline modules receive a `StateDB` instance for incremental processing.
- **index.py (VectorIndex)**: ChromaDB wrapper with 5 collections (sources, chunks, permanent_notes, mocs, `chapter_summaries`). Embedding provider configurable (OpenAI/SentenceTransformers/Ollama/Gemini) via the `_EF_BUILDERS` registry (ADR-052): a LangChain adapter routes Chroma's `embed_query` to the model's query side (Gemini `RETRIEVAL_QUERY`) and L2-normalizes when the model does not (the relevance floor assumes unit vectors); `embed_texts` stays on the document side. Credential readiness for web + `doctor` lives in `zettel/credentials.py`. There is no literature collection — LIT notes live in the vault and SQLite only. Upserts record estimated embedding usage on the active `CostTracker`.
- **vault.py**: Obsidian I/O — YAML frontmatter parse/render, managed blocks (`auto-backlinks`, `auto-connections`, `auto-moc-backrefs`, etc.), safe file writes that never overwrite manual edits outside managed blocks. Builders for SRC, literature **index**, and granular literature chunk notes. `sync_source_costs_to_vault` mirrors SQLite cost fields onto SRC frontmatter.
- **pricing.py / usage.py**: LiteLLM `cost_per_token` as price calculator only (not an LLM client); `CostTracker` aggregates per run/source via contextvars. Instrumented from `call_llm` and embedding upserts.
- **hashing.py**: Canonical text normalization (NFKC, whitespace collapse, PDF dehyphenation) before hashing. Layered checksums: file → extraction → chapter → chunk → llm_call → note_semantic. `compute_llm_call_checksum()` enables deterministic LLM response caching.
- **schemas.py**: Pydantic v2 models for all data objects and LLM structured outputs (LiteratureChunkOutput, PermanentNoteLLMOutput, DedupeResult, MOCGenerationOutput, ArticleOutline).

### CLI (`zettel/cli/`)

Typer + Rich, split into a package by pipeline phase (ADR-026 for the framework, **ADR-032** for the layout — same pattern as `harvester/` and `article_graph/`). Entry point: `python -m zettel <command>`, via `zettel/__main__.py` -> `from zettel.cli import main`. There is no `[project.scripts]`.

- **Infrastructure**: `app.py` (the `app`/`console` singletons), `deps.py` (composition root + the embedding-drift prompt), `formatting.py` (Rich renderers: `print_cost_by_phase`, `metrics_table`, the formatters), `options.py` (shared `Annotated` options + the flag resolvers `resolve_duplicate_flags` / `resolve_chunk_dump_dir` / `resolve_extraction_dump_dir`).
- **Commands**: `maintenance.py` (init, reindex, rebuild) · `ingest.py` (harvest, rechunk, set-paging, dump-chunks, dump-extraction) · `curation.py` (extract, review, retry-failed, summarize) · `synthesis.py` (connect, garden) · `purge.py` (purge-rejected, delete-source) · `manual.py` (new-note, sync-manual, suggest-links) · `pipeline.py` (run-all) · `qa.py` (ask, catalog) · `writing.py` (article) · `diagnostics.py` (status, doctor). `qa`/`writing` rather than `ask`/`article` because those modules import `zettel/ask.py` and `zettel/article.py`.

**Three rules a change here must respect** — all three are enforced by AST checks in `tests/test_cli.py`, not just documented:

1. **`app.py` imports nothing from the package.** Command modules import `app`/`console` from it, and `__init__.py` imports the command modules to trigger `@app.command()`; an import back into `app.py` closes the cycle and kills `python -m zettel`.
2. **Import order in `__init__.py` is the order of `zettel --help`.** Registration is an import side effect. The modules are bound to `COMMAND_MODULES` so an "unused import" cleanup cannot silently drop commands. `tests/test_cli.py` pins names *and* order.
3. **Domain modules are imported inside the command function, never at module scope.** That is what keeps `zettel --help` from loading chromadb/docling/langchain.

A shared `Annotated` option alias exists only when two or more commands declare the same flags with the same help text; where the flag means more in one command (`harvest --yes` also picks the duplicate action, `garden --yes` also confirms `--recreate`), that command declares it inline.

### Data flow between phases

`extract` writes drafts + concepts `awaiting_review`. `review` promotes approved concepts (after **same-source** dedupe) to `approved`. `connect` loads `get_concepts_by_status("approved", without_notes=True)` from SQLite only. All other inter-phase communication goes through StateDB and ChromaDB. Each CLI command instantiates `(AppConfig, StateDB, VectorIndex)` via `load_deps()`, `get_db()`, `get_idx()` in `cli/deps.py`.

**Breaking change**: the old monolithic LIT-per-source model is gone. Re-run `extract` + `review` for sources harvested before this change.

### LLM provider pattern

Shared helpers live in `llm.py` (`get_llm` / `call_llm` / `load_prompt_parts` / `fill_template`). `get_llm(cfg, phase)` instantiates the client for one consumer (`harvest`, `extract`, `review`, `connect`, `garden`, `ask`, `article`, `images`, `summarize`); identity is `llm.<phase>.{provider,model,base_url,temperature,thinking}` (`thinking: null` = vendor default; `false`/`0` disables; `minimal`/`low`/`medium`/`high` or a token budget) and sampling knobs (`temperature`, `top_p`, `max_retries`, `prompt_cache`) stay on `llm.`. Prompt files use `<!-- zettel:user -->` to split stable **system** instructions from per-call **user** payload; `call_llm` sends `SystemMessage` + `HumanMessage` so providers can reuse the prefix (OpenAI/Gemini implicit; Anthropic gets `cache_control` via `apply_prompt_cache_hints`; Ollama/OpenAI-compatible gateways are layout-only). `llm.prompt_cache` toggles hints; `llm.top_p` is forwarded to the LangChain client; per-phase `base_url` + aliases (`openrouter`/`opencode`/`deepseek`/…) cover OpenAI-compatible APIs; `deepseek` reads `DEEPSEEK_API_KEY`; `gemini` uses `ChatGoogleGenerativeAI`. Vision description uses `llm.images` (not `images.model`). `call_llm` reads `usage_metadata` (incl. provider `prompt_cache_read`/`write` tokens — distinct from SQLite `cache_hits`), estimates USD via LiteLLM's public price map, and records on the active `CostTracker`. SQLite `llm_cache` hits are `$0`. Pipeline commands (`harvest`, `extract`, `connect`, `garden`, `review`, `ask`, `article`) start/finish a `runs` row with cost totals — including `prompt_cache_read_tokens`/`prompt_cache_write_tokens` on the row itself (not just in-memory on the `CostTracker`), surfaced next to `cache_hits` in `zettel status`'s cost-by-phase table so the two cache layers (provider prompt cache vs. SQLite response cache) stay visually distinct; sources accumulate costs and SRC/ZTL frontmatter store them. Ollama / unknown models log tokens with `$0` cost. Upgrade `litellm` to refresh prices — no local price table to maintain.

## Important Conventions

- All generated content is in **PT-BR** by default (configurable via `config.yaml`).
- Vault note filenames follow pattern: `PREFIX - IDENTIFIER - slug.md` (SRC/LIT index use `AuthorYear`; granular LIT is `LIT - AuthorYear - pNNN - topic-NNNN.md`; ZTL/MOC use ULID). `@` belongs in `source_id` / CLI, never in vault paths.
- Vault structure: `00_Inbox/`, `10_Sources/`, `20_Literature/` (index at folder root + `{Citekey}/` granulares), `30_Permanent/`, `40_MOCs/`, `90_Assets/`.
- IDs: sources use `@citekey`, chunks use `source_id::chapter_id::short_hash`, notes/mocs use ULID.
- ChromaDB metadata only accepts str/int/float/bool — lists are joined with `", "` via `_sanitize_metadata()`.
- Windows cp1252 console: avoid Unicode arrows/special chars in CLI help strings (causes UnicodeEncodeError).
- This project uses UV for management dependencies
